# 码率预算与 bpp 判断

## 预算公式

```
视频码率(bps) = (目标字节 × 8 × 0.92) / 时长秒 − 音频码率
```

- **MB 一律按十进制**（70MB = 70,000,000 字节）。用户说 70MB、系统显示 66.8MiB，是同一个文件，别被"看起来更小"误导。
- **0.92 是安全系数**：x264/x265 的 ABR 实际输出普遍比请求值高 5–10%，封装再占 0.1%。
- 音频：AAC 128k 足够；纯人声 64k；源已是 AAC 就 `-c:a copy`，几乎不占预算。

例：70MB、105 秒、音频 128k
```
70,000,000 × 8 × 0.92 / 105 = 4,907,000 bps
减去音频 128k → 视频约 4.78 Mbps
```

## bpp：唯一能横向比较的指标

```
bpp = 视频码率 / (宽 × 高 × 帧率)
```

分辨率、帧率、码率三者任意两个变了，光看 Mbps 会误判。bpp 统一到"每像素每帧分到多少比特"。

### H.264 的经验区间

| bpp | 观感 | 典型场景 |
|---|---|---|
| < 0.01 | 明显糊，小字丢 | 别用 |
| 0.012–0.02 | 手机上能看，细节软 | 4K 夜景/低动态 |
| 0.02–0.035 | 日常观看 OK | 1080p 网络视频 |
| 0.05–0.08 | 质量不错 | 4K 高质量归档 |
| > 0.10 | 接近透明 | 母版 |

HEVC 在同观感下约为 H.264 的 **55–70%**：也就是 bpp 0.03 的 HEVC ≈ 0.045–0.05 的 H.264。

### 实测锚点（可直接对数）

| 素材 | 编码 | 码率 | bpp | 结论 |
|---|---|---|---|---|
| 3840×1696 30fps 日间行车 | HEVC | 21.4 Mbps | 0.109 | 源片，透明 |
| 3840×1696 30fps 日间行车 | HEVC | 8.7 Mbps | 0.044 | 几乎无差别 |
| 3840×1696 30fps 日间行车 | H.264 | 8.5 Mbps | 0.043 | 车牌清晰，暗部略平滑 |
| 3840×2696 30fps 夜景 | HEVC | 3.9 Mbps | 0.012 | 可看，细节软 |
| 3840×2696 30fps 夜景 | HEVC | 11.6 Mbps | 0.036 | 车牌清晰可取证 |
| 1920×1348 30fps 夜景 | HEVC | 6.7 Mbps | 0.086 | 清晰但明显不如 4K 细节 |

## 预算不够时，按性价比排序

1. **换 HEVC**（若目标设备支持）：同码率质量 +30~50%，或同质量省 30~40% 码率。
2. **放缓 preset**（medium→slow）：同码率质量 +5~10%，代价是编码时间翻倍。
3. **轻度降噪**（`hqdn3d=1.5:1.5:4:4`）：夜景噪点场景能省 20~40% 码率；白天收益小。注意会削弱细节，取证类素材要目视确认。
4. **降帧率**：30→24 省约 20%，但运动观感变差，一般不建议。
5. **降分辨率**：最后手段，且要用户同意——分辨率砍一半，码率再高也补不回小目标。

## 什么时候别压

源片 bpp 已经低于 0.05 时再压收益很小，可能只是多一次有损转码。先 `inspect.sh` 看一眼，再决定。
