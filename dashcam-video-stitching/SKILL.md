# 行车记录仪多视角拼接

把一段时间内的多路视频（典型：主视角 + 左/后/右）合成为一张画面，几何上不缩放不裁剪，体积可控，关键时段（车牌、碰撞瞬间）保持可辨认。

**核心顺序**：先定画布几何 → 再算体积预算 → 再按重要程度分配码率 → 逐段编码拼接 → 校验交付。顺序颠倒（先压再排版）会反复返工。

## 快速开始

以下命令在本 skill 目录下执行（`scripts/` 与 `SKILL.md` 同级）：

```bash
scripts/probe.sh <素材目录>                                    # 1. 侦察、算画布

scripts/stitch.sh -s <素材目录> --budget 70MB                  # 2. 看预算

scripts/stitch.sh -s <素材目录> -o out.mp4 \
  -d 105 -c 30 -b 90:15:27 --max-bytes 70MB                    # 3. 拼接（末 15s 提质量）

scripts/verify.sh out.mp4 --expect-duration 105 \
  --max-bytes 70MB --frames 90,104 --seam 90                   # 4. 校验取证
```

需要手机兼容版时，同样的参数再加 `--scale 1348` 出一份低高度副本。

## 1. 先侦察素材

```bash
scripts/probe.sh <源目录>
```

必须确认四件事，任何一项不对后面都会翻车：

| 检查项 | 为什么 |
|---|---|
| 各路时长/起始时间一致 | 不一致说明不是同一次录制，拼接会错位 |
| 帧率是否为 VFR | 记录仪常丢帧（如 avg 29.97 但标称 30），分段编码时必须统一成 CFR |
| 音轨是否数字静音 | 静音轨可以留（兼容性更好），但别以为没音轨就 `-shortest`，会截短视频 |
| 是否 10bit / 特殊像素格式 | 输出统一 `yuv420p` 8bit，兼容性最好 |

## 2. 定画布：几何无损

"无损"在拼接语境里指**不缩放、不裁剪、不改宽高比**。只要交付有体积上限就必然要重编码，所以对外表述是"几何无损 + 高质量重编码"，不要承诺 bit-exact。

常见素材天然可无损对齐：主视角 3840×1696、三路侧视角各 1280×1000 → 三个 1280 正好等于 3840，画布就是 **3840×2696**（主视角在上，左侧/后/右在下），四路全部 1:1 落位。

通用公式（主视角宽 `W`、侧视角 `w×h`、侧视角路数 `n`）：

```
tile_w = floor_even(W / n)
tile_h = floor_even(tile_w * h / w)
canvas = W × (H_main + tile_h)
```

不能整除时右侧留窄黑边即可，不要为了"填满"去拉伸。其他排版模板（2×2、主视角+右侧竖排、下排缩放到统一高度）见 `references/layouts.md`。

## 3. 算体积预算

```bash
scripts/stitch.sh -s <源目录> --budget 70MB    # 只打印预算与建议，不编码
```

- 目标字节数按 **十进制 MB** 保守理解，并预留 5–10% 余量给封装与音轨。
- 视频可用码率 ≈ `(目标字节 - 音频 - 封装) × 8 ÷ 时长`。
- 用 5–15s 样片试编码标定 CRF↔码率曲线再外推，别拍脑袋。**夜景/隧道噪声大会让码率成倍上涨**，白天数据不能套用到夜晚。
- 经验值（4K 画布、夜间城市道路）：0.4–0.5 bit/px 只能算"能看"，1.5–2 bit/px 才"干净"。

### 关键认知：别一超限就先降分辨率

小目标（车牌、路牌、文字）的可辨性主要由**像素数量**决定，分辨率砍一半，码率再高也补不回来。实测同一夜景 15s 片段：

| 输出 | CRF | 码率 | 车牌可辨 |
|---|---|---|---|
| 3840×2696 | 32 | 3.8 Mbps | 可辨 |
| 1920×1348 | 22 | 6.7 Mbps | 可辨但明显更糊 |

**4K 低码率反而比 1080P 高码率更清楚，还更省字节。** 只有在画布尺寸过不了设备解码上限、或目标体积确实压不下去时，才降分辨率。

## 4. 关键时段单独提质量

体积固定时，把码率从"不重要的时段"搬到"要取证的时段"是最有效的操作：

```bash
scripts/stitch.sh -s <源目录> -o out.mp4 \
  -d 105 -c 30 \
  -b "90:15:27"          # 第 90s 起 15s 用 CRF 27，其余用 CRF 30
```

实现方式：按边界切成若干段分别编码，再 `concat -c copy` 拼接。成立的前提（缺一样就会花屏或时间戳错乱）：

- 所有段的分辨率、帧率、像素格式、编码器参数完全一致；
- 每段从 IDR 开始（各自独立编码天然满足），拼接点不能有跨段参考帧；
- 源是 CFR（或编码时统一成 CFR）。

接缝校验：抽出接缝前后各一帧比亮度，或用 `scripts/verify.sh --seam 90` 看 `YAVG` 是否平滑过渡（场景自身自动曝光变化是正常的，编码引入的突跳才要查）。

## 5. 封装

- `-tag:v hvc1`：HEVC 在 Apple 生态/QuickTime 里必需，`hev1` 会打不开。
- `-movflags +faststart`：moov 前置，网页/微信里能边下边播。
- 音轨即使原样是数字静音也建议保留一条 AAC（体积可忽略，播放器兼容性更好）。
- 输出 MP4；只有需要多音轨/字幕等才考虑 MKV。

## 6. 校验与交付

```bash
scripts/verify.sh out.mp4 --expect-duration 105 --max-bytes 70000000 \
  --frames 90,104 --seam 90
```

逐项过一遍：时长/帧数、全片解码无错误、体积达标、关键帧 1:1 裁切目视车牌。

**必须目视验证车牌**：按 1:1 裁出目标区域，用最近邻放大 2–4 倍再截图——缩小显示会把糊掉的字符"看起来还行"，放大后才暴露问题。取证类交付不要只信码率数字。

### 兼容性预判

画布超过 **8.9M 像素**或高度超过 **2304** 时会落到 HEVC level 6.0，不少手机硬解不支持（见 `references/compatibility.md`）。稳妥做法是同时给一个高度 ≤2304 的通用版：

- 主交付：原始分辨率（几何无损）
- 兼容版：缩到 1920×1348 一类高度，给手机/微信转发

## 7. 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 拼接后花屏/绿屏 | 两段参数不一致，或用了不同编码器/预设 | 统一分辨率/帧率/pix_fmt/编码器，再 `-c copy` 拼 |
| 时长少了约 1 帧 | `-shortest` 遇上比视频短的静音音轨 | 去掉 `-shortest`，音频显式 `-t` 对齐 |
| 音画不同步 | 源 VFR，`-t` 截断后帧数与时间轴不符 | 滤镜里 `setpts=PTS-STARTPTS`，必要时 `fps=30` 固定 |
| 手机上提示"无法播放" | HEVC level 6.0 / 高度超解码上限 | 出 ≤2304 高的兼容版 |
| 拼接点亮度跳变 | 分段 CRF 差异过大 | 缩小两段 CRF 差距，或把切点放在场景切换处 |
| 编码极慢 | 4K x265 软编约 10 fps（16 核） | 分段并行编码；`-preset fast/medium` 权衡 |

## 8. 交付清单

1. 主交付视频（原始分辨率，几何无损）
2. 兼容版（可选，手机/转发用）
3. 校验数据：分辨率、时长、帧数、体积、码率分配
4. 复现脚本/命令，方便同一批素材重跑
