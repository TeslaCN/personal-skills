# 码率预算与 CRF 标定

## 预算公式

```
可用视频码率(bps) = (目标字节数 - 音轨字节 - 封装开销) × 8 / 时长秒
```

- **MB 按十进制保守取值**：用户说 70MB 时，按 70,000,000 字节设计，并预留 5–10% 余量。文件管理器常按 MiB 显示，同样的文件会"看起来"更小，但不能依赖这一点。
- 音轨：AAC 48kbps × 105s ≈ 0.6MB，静音轨更小，基本可忽略。
- 封装开销：MP4 约 0.1%，可忽略。

例：70MB / 105s → 约 5.2 Mbps 总码率，需要在这 5.2 Mbps 里做分配。

## 用样片标定，不要猜

```bash
# 取目标时段 15s，只换 CRF，看体积
scripts/stitch.sh -s <源目录> -o /tmp/probe.mp4 -d 15 -c 30 --no-audio
ls -l /tmp/probe.mp4
```

得到 CRF→码率的点，再线性外推（CRF 每 +1 约省 15–20%，但不同内容差异很大）。

## 实测参考值（4K 画布 3840×2696，夜间城市道路，30fps）

| CRF | 码率 | 用途判断 |
|---|---|---|
| 20 | 41.7 Mbps | 准无损，仅用于极短片段 |
| 26 | 13.8 Mbps | 车牌边缘基本无损 |
| 27 | 11.6 Mbps | 车牌清晰，取证够用 |
| 30 | 5.6 Mbps | 全画面可看，细节略糊 |
| 32 | 3.8 Mbps | 小字仍可辨，暗部有涂抹 |

同一场景 1920×1348：CRF 22 → 6.7 Mbps。

**这些数字只对"夜间城市、有大量灯光噪声"的场景成立。** 白天、晴天、静态停车画面码率会低得多（可能只有 1/3）。隧道口明暗交替、雨刷、雨夜反光会显著推高码率。

## 分配策略

按"信息价值"而非"时长比例"分配：

```
总预算 65MB / 105s
├─ 0–90s（普通行车画面）   CRF 30  → ~43MB
└─ 90–105s（取证关键段）   CRF 27  → ~22MB
```

关键段到底给多少？判断标准是**放大 1:1 看车牌/文字**：

1. 从目标时刻裁 500×240 区域；
2. 最近邻放大 2 倍存 PNG；
3. 目视判断字符边缘是否完整。

看得清就停，继续加码率没有收益（CRF 26→24 在 4K 上肉眼已无差别）。

## 码率不是唯一手段

按性价比排序：

1. **换更慢的 preset**（`medium`→`slow`）：同码率质量 +5~10%，代价是编码时间翻倍。
2. **关键段提 CRF**：最直接，前提是预算够。
3. **加轻量时域降噪**（`hqdn3d`）：夜间噪点场景能省 20–40% 码率，但会削弱车牌的细微笔画，取证场景慎用、且必须目视验证。
4. **降分辨率**：最后手段，见 SKILL.md 第 3 节的实测对比。

## 体积失控的排查顺序

1. `-t` 是否生效（源文件比目标长时忘了截）；
2. 音频是否被重编码成高码率；
3. 关键段是否过长（15s 的 CRF 25 就有 35MB）；
4. 是否误用了 `-crf` 与 `-b:v` 同时指定（ABR 会压过 CRF）。
